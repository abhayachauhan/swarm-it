# Command and event contract (FROZEN at G1)

Only the orchestrator may change this file (Phase 2e hardening edits authorised by the orchestrator), `state.d.ts`, `manifest.schema.json` or `kelpi.plugin.json`.

All names are declared in `kelpi.plugin.json` and registered in `backend/index.mjs`. Views call
commands with `api.commands.execute(id, args)`. Every result is a `CommandResult` (see `state.d.ts`):
`{ ok: true, ... }` or `{ ok: false, error, code? }`. Handlers never throw for expected refusals.
Argument objects are plain JSON. `paneID` always means the Kelpi pane id (never a label).

The rail's Auto toggle, when off, opens a menu of 10 minutes, 4 hours, 12 hours and until 9am (local; today when it is before 9am, else tomorrow); it never offers "until turned off". When on, one click turns it off. Off by default and after every install or reload: the on state is never persisted. Unrecognised prompts are left for the user and counted in `skipped`. A refused approval (`STALE`, `NOT_WORKER`, ...) is logged with the reason, counted in `failed`, never retried on that card, and leaves the card. Rate guard: more than 30 auto-approvals on one pane in 10 minutes pauses that pane (`paused`, with the reason); its cards are left. When the time runs out it switches itself off (`ended.reason = 'expired'`); the rail announces that once as a footer notice, as it does a rate-guard pause, and afterwards both stay in the Auto toggle's tooltip (a switch-off by the user is not announced). Snoozed cards are left alone. The same prompt (same hash) on the same pane is not approved again within 15 s of an approval: a prompt still showing right after Enter did not take the key and must not be fed Enter every scan. Never-auto-approve list (`NEVER_AUTO_APPROVE`, exported by `autoapprove.mjs`): a command containing `rm` with a recursive flag in any order (`-r`, `-rf`, `-fr`, `-f -r`, `-R`, `--recursive`), `git push`, `sudo`, a download piped into a shell (`curl`/`wget` with a `sh`/`bash`/`zsh`/`dash`/`ksh` segment), `mkfs`, `dd ... of=`, `find ... -delete` or `-exec rm`, `git clean` with `-f`, `git reset --hard`, `git checkout -- .` / `git restore .`, `rsync --delete`, `gh pr merge`, `gh repo delete`, `npm`/`yarn`/`pnpm publish`, `kubectl delete|apply|replace|scale|drain|patch|edit|create`, `terraform`/`terragrunt`/`tofu apply|destroy`, `helm install|upgrade|uninstall|delete|rollback`, `aws` with a write subcommand (`delete-*`, `put-*`, `create-*`, `update-*`, `terminate-*`, `modify-*`, `remove-*`, `s3 rm|mv|rb`, `s3 sync --delete`), a download piped into an interpreter (`python`, `node`, `perl`, `ruby`, `php`, `deno`, `bun`), a segment whose command word is a variable (`$R -rf x`, `${X}`; `echo $HOME` is fine), any use of `alias` or `eval`, shell expansion that builds a word (a command word containing `{` or `$` such as `{rm,-rf,x}`, a `${...}` with an operator such as `${X:-rf}`, a flag containing `$`, or `$`/`}` glued to letters such as `git ${x}push`; `echo ${HOME}/x` is fine), anything piped into a shell or interpreter (`echo ... \| base64 -d \| sh`, `cat x.sh \| bash`, also `\| "sh"`, `\|& sh`, `\| command sh`), a shell or interpreter fed generated code (`$(`, backticks, `<(`, `<<`, `<<<`, `base64`, `xxd` or `printf` anywhere in the command), a command word that comes from a substitution (`$(echo rm) -rf x`), an ANSI-C quoted word with escapes (`$'\x72m'`), `xargs`/`parallel` running `rm`, or `git -c alias.*` / `--config-env` is left as a card. Tokens are read as the shell would: `$'rm'` and `$"rm"` read as `rm`, a backslash-newline joins its halves, `=rm` and `Rm` read as `rm`, `--rec` counts as `--recursive`, and wrapper options (`time -p`, `env -i`, `exec -a name`) are skipped to find the command word. All of these are counted in `skipped` and logged once with reason "on the never-auto-approve list" (`code: 'NEVER'`, `rule`). Every segment is checked (split at `&&`, `\|\|`, `;`, `\|`, `&`, newlines, `$(...)`, backticks; quotes and backslashes deleted first, so `r"m" -rf` counts), and a wrapped command also with its lines joined. Manual Approve is unaffected. Approve (manual or auto) is refused with `STALE` when the pane is idle with no agent session: that is a plain shell, and a prompt left on its screen must never get Enter. The prompt scan skips such panes unless a card or waiting row for them still needs settling. |

No git check and no pane close: nothing runs any more. Never edits the manifest file. Running and waiting rows show a two-step Stop (`close-worker`) on the selected or hovered row only; X does the same. |
| `local.swarm-view.auto-approve-log` | `{ clear?: true }` | `{ ok, entries: AutoApproveEntry[], count }` | The persisted log (last 500, storage key `autoApproveLog`), newest first: time, swarm, worker label, command, and the reason when refused. `clear: true` empties it. |

## Error codes

`BAD_ARGS` missing or wrong-typed argument. `BAD_TEXT` text breaks the text policy. `BAD_LABEL` a worker label outside `^[A-Za-z0-9._ -]{1,40}$`. `NOT_FOUND` unknown item. `NOT_REQUEST` item is not a Request. `HANDLED` item already handled. `NOT_WORKER` pane is not in the manifest worker list (applies to capture-worker, read-result, send-to-worker, open-result, accept, archive, open-thread). `NO_RESULT` no or unreadable `resultPath`. `NOT_FINISHED` accept on a worker that is not done or error. `NO_PANE` pin-orchestrator on an unknown pane. `STALE` the live prompt is gone, the pane is not waiting for input, or (approve) the prompt differs from what was displayed. `DIRTY`, `UNKNOWN_GIT` archive refusals. `NO_SESSION` send-to-worker on a finished worker whose Claude session id is unknown. `NOT_AT_CLAUDE` send-to-worker on a worker with no result whose pane does not show Claude's input box and that Kelpi does not report as ended. `PROMPT_OPEN` send-to-worker while the worker pane shows a permission prompt or cannot be captured. `NO_ORCHESTRATOR`, `IS_WORKER`, `SEND_FAILED`, `CAPTURE_FAILED`, `OPEN_FAILED`, `INTERNAL`. Added in hardening pass 2 (additive): `BAD_RESULT_PATH` (read-result/open-result: extension not in .md .txt .json .csv .log, or the resolved real path is outside the worker's worktree or the trusted workspace root) and `NOT_APPROVABLE` (approve/deny on a Request whose prompt shape was not recognised, `approvable: false`).

## Text policy (send-to-worker, and every message the backend types into a terminal)

1 to 4000 characters. Newline is allowed between lines but not at the end. No other control character: no ESC, CR, NUL, backspace, tab, DEL or C1. Violations return `BAD_TEXT` and nothing is sent. Messages the backend builds (for example accept) use only validated labels and pane ids.

## Manifest validation

Labels must match `^[A-Za-z0-9._ -]{1,40}$`. `resultPath` and `worktreePath` must be absolute, with no `..` segment and no control character. An invalid manifest is rejected whole.

## Prompt parsing

A permission prompt counts only when its question sits within the last 12 non-empty lines of the capture. `command` is every line between the header and the question, joined with newlines. `promptHash` is sha256 over the whole block (header through last option, lines trimmed and whitespace-collapsed), so changing any line changes it.

## Status bar item

`local.swarm-view.counts` (placement `statusbar`, declared in `items`). Backend updates it with
`api.contributions.update({ items: { 'local.swarm-view.counts': { text, badge, tone } } })`.
Text format: `Swarm <waiting>/<running>/<finished>`. Tone: `warning` if waiting > 0, else `error` if any error, else `info` if running > 0, else `default`.

## Storage keys (plugin storage, backend only)

`attention` (AttentionItem[]), `pins` ({ orchestratorPaneID }), `accepted` (paneID[]), `archived` (paneID[]), `firstSeen` ({ [paneID]: ISO }), `hiddenWorkspaceID`, `autoApproveLog` (AutoApproveEntry[], last 500; the auto-approve on/off state itself is never stored), `gone` (paneID[] seen closing) and `results` (paneID[] whose result file was proven to exist while the pane was live; existence is sticky once the pane is gone, since the path check needs the live pane to trust the worktree), `sessions` ({ [paneID]: last Claude session id }) and `restarts` ({ [paneID]: sha256 of the result file when send-to-worker restarted it }).

## Message budget

Kelpi stops a plugin that sends more than 512 messages in one second ("plugin exceeded the IPC message
rate limit"), and the rail disappears. So `persist` writes only the storage keys whose value changed, the
status bar item is updated only when its text or tone changes, and a burst of attention changes inside one
queued task (a pane closing with many open cards) publishes the snapshot once. Settling 60 cards at once
used to send about 690 messages; it now sends well under 140 (test/backend-message-budget.test.mjs).

## Collapse (G0: HIDE)

Workers listed in a manifest are moved with `api.panes.moveToWorkspace(paneID, workersWorkspaceID)` into one shared workspace named `Workers`, for every swarm. It is created in a Group named `Workers` (created when missing, then collapsed); without a Group API it sits at the top level. An existing `Workers` workspace is reused, the one in the `Workers` Group first. Everything is addressed by pane id; labels do not resolve across workspaces. Moving back (`showWorker`) is supported. Which swarm a worker belongs to comes from the manifests, never from where it sits: the ownership gates accept a listed worker in the swarm's own workspace, in `Workers` (matched by name), or in the swarm's old `<name> · workers`. Because every swarm shares `Workers` and any local process can write a manifest, a pane outside the swarm's own workspace is refused while another live manifest also lists it (`claimedElsewhere`): it is never messaged, approved, moved or closed. At most `BATCH_PER_SCAN` (8) workers are moved per scan, and at most 8 closed by auto-clean, so a first install moving dozens of workers stays under Kelpi's 512 messages a second. Workers still in an old `<name> · workers` are moved to `Workers`. `get-state { workspaceID }` resolves any workspace in a Group to the Group workspace that has a manifest, so a swarm owns its Group; `Workers` itself belongs to no swarm, so following it shows only the other-swarms list. Layout regain on the orchestrator workspace is not yet measured (spike REPORT.md).

A move that fails (for example the host's "plugin invocation has expired") is retried with backoff: 10 s, 30 s, 2 min, then every 5 min (`HIDE_RETRY_MS`, overridable with `SWARM_HIDE_RETRY_MS`), on the prompt-scan timer. The `collapse:` warning stays while a move is pending and clears once every move has worked, or once the pane closed or is no longer a worker of the followed swarm (following another workspace drops every pending retry); the `autohide:` warning names the workers waiting for a retry. Creating `Workers` leaves the host's shell pane in it, and the plugin keeps it: `Workers` never empties, so it is never recreated (creating a workspace switches the user's view). Collapse never closes a pane.

## Auto-clean

On the prompt-scan timer, every finished worker of the followed swarm (gate `actionableWorker`) and of every other live swarm (gate `otherSwarmPane`) is timed from the moment it is first seen finished: result file present and agent not running, or pane closed. After `autoCleanMinutes` (setting, default 10; 0 turns it off) its pane is closed (a closed pane is just removed), it is marked archived and its open cards are settled. An errored worker with an open pane, and running or waiting workers, are never touched. Before closing, the worktree must be clean: a dirty worktree or an unknown git status keeps the worker, names it in the `autoclean:` warning and tries again after another delay; a refused close does the same. The timer is in memory, so a plugin reload restarts it. Empty, inactive workspaces named `<name> · workers` (from before the shared workspace) are removed with `api.workspaces.remove`, each tried once per plugin run; nothing else is removed.

Prompt parsing in a narrow pane: the newer ruled layout accepts up to 6 wrapped description lines before the first rule, up to 10 note lines after the second, a question wrapped over two lines, and a corner-only frame line (`╭─╮`) above the header. The header may end with " · from the <name> agent" and, while several agents wait at once, a right-aligned queue counter ("1 of 3", after two or more spaces); nothing else may follow it. The command is still exactly the lines between the two rules, and the rail shows those raw lines. Only a real terminal wrap (three or more lines, every non-final line the same width, the last no wider) has its mid-token splits rejoined for display, each join marked with `⏎`. The card clamps the command to two lines (a line says how many are hidden; a wrapped single line is measured after layout and again whenever the rail is resized); a click or Enter expands it in place. Approve, Deny and "Really stop?" are disabled for 400 ms after a layout change the user caused under the pointer (a card expanding or collapsing, Stop being armed or cancelled), so the second click of a double-click never lands on them; after arming Stop, Keep takes the spot Stop had and "Really stop?" sits beside it. An unrecognised prompt's card says "Answer in the pane" and offers "Go to pane", which reveals the pane itself (`api.ui.reveal`), whichever swarm it belongs to. Cards show only Request items: Complete and Error items are never drawn, finished workers are only counted in the Done section's head, never listed. Snapshot `warnings` are not drawn in a footer: the rail logs them to the console and shows a small "⚠ N" in the header whose click expands them. The rail reads in a dark and a light host theme: its colours come from `--kelpi-*` tokens when the host sets them, else from a palette per `prefers-color-scheme`.

## Rail fixes (additive)

Waiting worker the rail cannot read: a pane a few columns wide wraps a prompt one word per line and `parsePrompt` finds nothing. The prompt scan counts, per scanned worker of any live swarm that is not done, consecutive scans where the pane status is `waitingForInput` and no prompt parses; at two it lists the worker in snapshot `waitingPanes`. A worker whose result file exists is done (a finished headless worker's shell also reports `waitingForInput`): the scan re-checks the result file before counting. The entry clears when the pane's status changes or it closes, when a prompt parses (the normal card takes over), or when the worker is no longer scanned. The rail shows it under Needs you as "<label> is waiting for you" with Go to pane (`api.ui.reveal`; Enter does the same). It is not an attention item: nothing approves it, auto-approve included.

Other swarms: snapshot `otherSwarms` has one entry per live swarm other than the followed one, with running, need-you and done counts and its Group colour (`api.groups.list`, matched through the workspace's `groupID`; only Kelpi's named colours pass, else null). The rail draws one line per entry below the followed swarm's sections, "<name> · N running · N need you · N done" with zero parts left out; a click reveals that swarm's coordinator pane. Nothing is drawn when there are none.

Cards and waiting rows from another swarm carry a small "from <swarm name>" tag at the top in that swarm's Group colour (`data-color`, the accent when it has none); a click on it reveals that swarm's coordinator pane.

## Private CLI

Workers and tests never call bare `kelpi`. Use `bin/k` with `SWARM_VIEW_SOCKET=tcp:127.0.0.1:56353`. Only `kelpi plugin validate` may run unwrapped.

## Settings: worktree trust (additive)

`worktreeRoots` (string, default empty): absolute directories separated by `:` or newlines. A manifest worker's `worktreePath` scopes its result files only when its real path is strictly inside one of `worktreeRoots` (empty means `<home>/repos`), `resultRoot` or the manifest directory. `/`, the home directory and any ancestor of home are never trusted, as roots or as worktrees. Results with no trusted worktree are limited to the manifest directory (never its parent) and `resultRoot`.

## Added: run last suggested command

Claude Code wraps a long suggested command itself (a real newline plus indent), so copying it gives a broken command. These commands find the last suggestion in a pane and undo those wraps. Logic in `backend/suggested.mjs`; view `local.swarm-view.run` (`ui/run/`). "Run last suggested command" is in the pane header and pane menu (`when: { "pane.type": "shell" }`) and the palette; "Copy fixed command" in the pane menu and palette.

| Command | Args | Result | Notes |
|---|---|---|---|
| `local.swarm-view.run-suggested` | `{ paneID? }` | `{ ok, command, viewPaneID }` | Source pane: `paneID`, else the invocation context's `paneID`, else the focused pane in the active workspace (`NO_PANE`). Captures its last 200 lines with scrollback (`CAPTURE_FAILED`) and finds the suggestion (`NO_COMMAND`). Opens the run view with state `{ mode: 'run', sourcePaneID, command, kind, targets }` in the source pane's workspace, closing the previous run view. Types nothing. |
| `local.swarm-view.copy-suggested` | `{ paneID? }` or `{ text }` | `{ ok, command, copied: true }`, or the `run-suggested` result | Puts the joined command on the clipboard (the plugin API has none, so the backend runs `pbcopy`). With no clipboard it opens the run view in `mode: 'copy'` instead. With `text` (the view's Copy button) it copies exactly that text, `BAD_TEXT` by the text policy, `NO_CLIPBOARD` when copying fails. |
| `local.swarm-view.run-suggested-confirm` | `{ sourcePaneID, text, target, confirmed: true, allowAgent? }` | `{ ok, paneID }` | The only command that types. `NOT_CONFIRMED` unless `confirmed === true` (only the view's Run button sends it). `text` follows the text policy (`BAD_TEXT`: control characters refused). `target: 'new'` (the default) splits a shell next to the source pane in its working directory (`panes.split`, `OPEN_FAILED`); a pane id types into that pane (`NO_PANE`, `NOT_SHELL`), and a pane running an agent is refused with `AGENT_PANE` unless `allowAgent: true`, which the view sends only when the user picked that pane. Sends with `terminal.send` (Enter appended), then closes the run view. |
| `local.swarm-view.close-run-view` | `{}` | `{ ok, closedViewPaneID }` | Closes the run view this plugin opened last, or nothing. The view's Cancel button. |

Finding the suggestion (`findSuggested`): the LAST of a line starting `! ` (after optional indent and Claude's `⏺`; the `! ` is stripped), a fenced block (```` ``` ````, ```` ```bash ````, ```` ```sh ````, ```` ```shell ````, ```` ```zsh ````; unclosed fences and other languages are ignored), or an indented line directly after a line starting `Run` (one blank line allowed). Wraps: a line indented by exactly the block's indent plus two continues the line before (never after a line ending in a shell `\`); other lines are separate commands and keep their real newlines. The join is one space, except no space when the line before ended without a space AND filled the wrap width (at least the width minus one), which means the wrap split a token such as a URL. The wrap width is the widest full rule line (`─` and kin, 20 or more) in the capture, the pane width Claude Code draws its input box at; with none, nothing counts as filled and the join is a space.

The run view shows the command in an editable text box and a "Run in" menu defaulting to "A new shell pane next to this one", then the source workspace's shell panes (agents labelled). Run, Copy and Cancel; empty text, control characters and invisible format characters (`\p{Cf}`: bidi overrides, zero-width) are refused in the view as well as in the backend. A multi-line command shows "N lines: each runs as its own command." and the text box grows to fit (up to 20 rows).

## Added: restart Claude

"Restart Claude (quit and resume)" is in the pane header, the pane menu (`when: { "pane.type": "shell" }`) and the palette. Logic in `backend/restart.mjs`.

| Command | Args | Result | Notes |
|---|---|---|---|
| `local.swarm-view.restart-claude` | `{ paneID? }` | `{ ok, paneID, session, resumed: true }` | Pane as for `run-suggested` (`NO_PANE`); a terminal only (`NOT_SHELL`). Session: Kelpi's live `agentSessionID`, else the plugin's saved copy in `sessions`, which outlives Claude exiting (`NO_SESSION`). Refused, typing nothing, when the pane shows a permission prompt (`PROMPT_OPEN`), Claude is mid-reply (`BUSY`), the last 20 lines say background agents are running (`BACKGROUND`), or Claude's input box holds text (`INPUT_NOT_EMPTY`; the dim `Try "..."` hint of an empty box counts as empty). At Claude's input box it types `/exit`, then waits up to 15 s, looking every 250 ms, until the input box is gone and either Kelpi cleared the session or Claude printed "Resume this session with" (`EXIT_TIMEOUT`, nothing more typed); 500 ms later it types `claude --resume <id>` without Enter, checks the shell's last line, and only then presses Enter. Kelpi types text as a bracketed paste, and a shell with a broken paste widget keeps the paste end's `~`: one stray `~` is erased with Backspace; any other mismatch leaves the line unsent (`TYPED_WRONG`). A pane already back at its shell gets the resume line at once. The reply waits for the resume line because the host refuses calls made after a command replied; it runs outside the serial queue. A refusal is thrown, not returned, because the pane menu shows only a thrown error (as a toast). The resumed Claude starts with default flags: a `--permission-mode` or `--model` given at the first launch is not repeated. |
